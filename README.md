# [SDK 58][expo] `"extends": "expo/tsconfig.base"` no longer resolves in exports-aware tools: the `"./*"` export maps it to `tsconfig.base.js`

## Summary

On Expo SDK 58, a `tsconfig.json` that uses `"extends": "expo/tsconfig.base"` (the form in the `blank-typescript` template, the TypeScript guide, and the file generated by `npx expo customize tsconfig.json`) can't be resolved by tools that follow Node's `exports` rules. In this repo that shows up as an ESLint error from `eslint-import-resolver-typescript`: `Resolve error: Tsconfig not found expo/tsconfig.base`.

`expo@58` added an `exports` map to its `package.json`. Its catch-all entry `"./*"` maps extensionless subpaths to `./*.js`, so `expo/tsconfig.base` resolves to `tsconfig.base.js`, which doesn't exist. `expo@57.0.30` has no `exports` map, so Node's resolver tried adding `.json` and found `tsconfig.base.json`.

Changing the extends value to `expo/tsconfig.base.json` resolves in every tool tested. The `./*.json` export entry handles it.

## Steps to reproduce

```bash
git clone https://github.com/daemosity/expo-sdk58-tsconfig-extends-repro.git && cd expo-sdk58-tsconfig-extends-repro && npm ci
node -e "console.log(require.resolve('expo/tsconfig.base'))"    # fails
npx eslint App.tsx                                              # fails
npx tsc --noEmit                                                # passes
```

The Node resolution failure is present from the first commit ([`cd8b26f`](https://github.com/daemosity/expo-sdk58-tsconfig-extends-repro/commit/cd8b26f60450000b083a8730bc16df2e6d9f6d4b)). The ESLint error appears once ESLint is configured ([`8463377`](https://github.com/daemosity/expo-sdk58-tsconfig-extends-repro/commit/84633770dfc1cb1020de3715e127d42a6f4cca76)).

Control: switch to the `.json` form, and every check passes.

```bash
sed -i 's#"expo/tsconfig.base"#"expo/tsconfig.base.json"#' tsconfig.json
node -e "console.log(require.resolve('expo/tsconfig.base.json'))"  # resolves
npx eslint App.tsx                                                  # no errors
git restore tsconfig.json                                          # restore the failing state
```

## Expected vs. actual

**Expected:** The `extends` value that Expo's template, docs, and CLI generate resolves in tools that follow Node's `exports` rules, as it did on SDK 57.

**Actual:**

| Check | `"extends": "expo/tsconfig.base"` | `"extends": "expo/tsconfig.base.json"` |
|---|---|---|
| `node -e "require.resolve(...)"` | fails: `MODULE_NOT_FOUND` for `.../expo/tsconfig.base.js` | resolves to `.../expo/tsconfig.base.json` |
| `npx eslint App.tsx` (`eslint-import-resolver-typescript`) | fails: 3 errors (`Tsconfig not found expo/tsconfig.base`, plus `Unable to resolve` for `expo-status-bar` and `react-native`) | no errors |
| `npx tsc --noEmit` | passes | passes |

### Scope

- **Breaks:** Node's own resolution (`require.resolve`), and tools that resolve the `extends` value with an `exports`-aware resolver. Here that's `eslint-import-resolver-typescript`, which uses `unrs-resolver`.
- **Doesn't break:**
    - TypeScript. `tsc` 6.0.3 resolves both forms, so type checking and editor tooling based on `tsc` work.
    - `expo-doctor`. `npx expo-doctor` passes 20/20 with the extensionless form.
    - Metro. Expo CLI's tsconfig loader resolves `extends` with its own lookup that ignores `exports`, so `"expo/tsconfig.base"` still resolves when bundling (checked with `npx expo export --platform android`, using a `paths` alias defined only in the base config).
- **Side effect:** When the resolver can't load the tsconfig, every import in the file also fails to resolve. With the extensionless form, the `expo-status-bar` and `react-native` errors above come from the tsconfig error, not from separate problems. They go away when the `.json` form is used.

## Where the extensionless form comes from

- **Template:** [`templates/expo-template-blank-typescript/tsconfig.json`](https://github.com/expo/expo/blob/59dfdddbc0ba848435363f0c731b11eea59cc62f/templates/expo-template-blank-typescript/tsconfig.json#L2)
- **Docs:** [TypeScript guide](https://docs.expo.dev/guides/typescript), which says a project "should extend `expo/tsconfig.base` by default" and uses that form in three examples ([source](https://github.com/expo/expo/blob/59dfdddbc0ba848435363f0c731b11eea59cc62f/docs/pages/guides/typescript.mdx#L111))
- **CLI:** `npx expo customize tsconfig.json` (`@expo/cli@58.1.11`) generates `"extends": "expo/tsconfig.base"`
